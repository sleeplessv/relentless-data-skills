# Glossary

Ubiquitous language for this repo's skills. Glossary only — no implementation details.

## Terms

- **Skill**: an independently versioned bundle of agent instructions and supporting files. Its documentation belongs to the same bundle.
- **Skill update**: a set of changes delivered together to one skill. Documentation corrections count as updates, even when the skill's behavior stays the same.
- **Skill version**: the identifier of a skill revision, used to track changes and support updates to installed copies.
- **Ticket** — the unit of implementable work. On GitHub or GitLab the ticket is stored as an issue; the skills' mechanics use GitHub (`gh`).
- **Integration branch** — the branch created off the default branch (`main` in most repos) for a whole feature; all per-ticket work for that feature lands here before anything reaches the default branch.
- **Session ticket**: a ticket drafted from the current Claude Code session's discussion, confirmed by the user, and filed as an issue before implementation starts. Once filed it is an ordinary ticket. _Avoid_: chat ticket, ad-hoc ticket, ticket-less run.
- **Ticket branch**: a branch for one ticket. Each feature dispatch starts from a pinned integration commit. Its temporary branch remains until verified integration preserves its commits and cleanup proves ownership.
- **Feature PR** — the single pull request from the integration branch into the default branch. In generation one it is the only PR a feature produces; in generation two each ticket also has a ticket PR into the integration branch.
- **Spec**: a specification stored as an issue, labelled `spec` or the older `prd`. Tickets divide its implementation. A spec-only feature run promises its full requirements; an explicit ticket set uses it as context.
- **Work-set**: the resolved list of tickets a run will implement, announced before work starts. An explicit ticket list controls this scope.
- **Deepening candidate**: a proposed refactor, produced by an architecture review, that turns a shallow module into a deep one. It carries the files involved, the problem, the proposed solution, and a recommendation strength.
- **Decision log**: the answered design tree for one deepening candidate, each decision paired with its evidence. The spec for that candidate is written from it.
- **Decision list**: in generation one, the record of one run's decisions, each with its reason and who made it: the user, the coordinator, or a worker. Generation two keeps a run record. _Avoid_: decision log (the answered design tree for a deepening candidate).
- **Final review**: the single-pass quality review run by a worker that wrote none of the change and sees none of the other reviews, as part of the check wave, whose findings the coordinator triages. _Avoid_: ponytail review (names the tool, not the gate), sanity check, last pass.
- **Check wave**: the reviews of one change that run together on one commit after implementation. _Avoid_: review chain, review stages.
- **Fix round**: one fix of the findings accepted so far, with the re-check of that fix when it needs one. _Avoid_: review loop, iteration.
- **Late fix**: a change committed after the fix rounds are over.
- **ADR-level fix**: a fix that contradicts a recorded architecture decision, or makes a choice that would warrant recording one. _Avoid_: architectural fix, one-way fix.
- **Closing verification**: the clean-checkout rerun of a change's checks on the commit that will ship, by a worker that wrote none of the change. _Avoid_: independent verification, mop-up.
- **One-way door**: a change whose effects reverting it would not undo, such as a data migration, a published release, or a permissions change. A change of uncertain type is treated as one-way.
- **Two-way door**: a change that reverting fully undoes.
- **Model class**: a level of model capability that a role or a task is assigned to. The classes are apex, strong, standard and light, and the `router` skill names the model for a class. Generation one's classes are session, strong and standard, each named by an alias that follows the level's newest version. _Avoid_: model tier, model version.
- **Session class**: the model a session runs on, chosen by the person who started it. Generation one assigns work to it as a model class; generation two assigns no role to it.
- **Class escalation**: moving a task whose result failed its check to a fresh agent on the next **model class** up. Generation one and the `router` skill escalate. Generation two has no class escalation.
- **Route**: the model, reasoning effort and **harness** chosen for one task, with the same-class model to use when the chosen one cannot be reached. _Avoid_: dispatch channel, mode.
- **Promotion**: moving one version of the work to its next stage, such as a release branch, a deployment stage, or production. _Avoid_: advancing.
- **Promotion check**: a check required before a promotion, tied to the place where it must pass.
- **Review workspace**: the directory a verifier or reviewer owns under the run directory. It holds the worker's detached checkout and scratch files. _Avoid_: reviewer worktree, scratch checkout.
- **Frontier**: in generation one, tickets with no active implementer whose blockers are satisfied in the verified, preserved integration tip; assignment to the authenticated actor is advisory there and does not make that actor an active implementer. In generation two, the tickets of a work-set that are open, unclaimed and have no open blocker.
- **Dispatch base**: the immutable integration commit assigned to a ticket attempt. Concurrent attempts can have different bases as integration advances.
- **Completion mode**: the obligations a feature run must satisfy. A whole-spec run covers every spec requirement; a selected-ticket run covers its explicit work-set.
- **Orchestrated dispatch**: a ticket worker invocation with an assigned immutable base commit, inherited original baseline, satisfied blockers, and coordinator-owned issue and PR actions.
- **Baseline**: in generation one, the original base commit and its recorded check results. Later dispatch commits and integration failures remain distinct from this original evidence. _Avoid_: baseline for a comparison group (that is the single-agent baseline).
- **Handoff files**: durable shared artifacts containing scope, ticket snapshots, exploration notes, commands, and decisions. Workers exchange their paths and update the run record as work completes and integrates.
- **Generation one**: the implementation and orchestration skills in use before the redesign: orchestrator-mode, implement-ticket, implement-feature and implement-backlog. _Avoid_: v1, the old stack.
- **Generation two**: the skills built beside generation one to replace it: deliver for ticket work and squad for non-ticket work. _Avoid_: v2, the new stack.
- **Harness**: the agent program a session runs in, such as Claude Code, Cortex Code, Codex, Cursor or Antigravity. A harness is distinct from the model it runs. _Avoid_: tool, agent, IDE.
- **Carry**: a **harness** carries a model when it can run a session or a **helper** on that model. One harness can carry models from several vendors. _Avoid_: support, host, have.
- **Supported harness**: a harness on which every generation-two skill must reach the same result and pass the same checks as on any other supported harness.
- **Adapter**: the text a session on one supported harness reads for the steps that harness does differently from the harness a skill is written for. That harness itself has none. _Avoid_: harness notes.
- **Harness files**: the definition files, hook registration and preflight figures that one supported harness needs. Every supported harness has them, where only some have an adapter. _Avoid_: adapter (the text only).
- **Check**: in generation two, a command run against a change that ends in pass or fail, such as a test, a build, or a run of the changed thing. _Avoid_: verification, verifier; check for a reading of a change (generation one's check wave is made of reviews).
- **Review**: in generation two, a reading of a change against stated criteria by an agent that wrote none of it. _Avoid_: verifier, verification, check.
- **Check plan**: the list written before a change is made that pairs each of its requirements with the check or review that will prove it. _Avoid_: test plan.
- **Counted pass**: a saved check that counts as evidence for a change: it passed, it selected something, and it ran on the final commit with no uncommitted change. _Avoid_: green run, passing check (a check can pass and not count).
- **Entry check**: in generation two, the check that a ticket holds what a run needs before an author starts on it: what to build, and at least one requirement that can be proven. _Avoid_: triage (deciding whether a ticket should be worked at all), readiness check.
- **Small edit**: in generation two, a two-way door change that stays within the line limit and has a low blast radius. It is the size of change that needs no review. _Avoid_: trivial change, quick fix.
- **Blast radius**: everything else that can break or give wrong results if a change is wrong. It is high when the change touches a critical path, or when more depends on what it changes than the limit allows. _Avoid_: impact, risk level.
- **Critical path**: a part of a repo where every change gets a review, whatever its size. _Avoid_: protected path, sensitive file.
- **Owner**: in generation two, the person who started a run and answers its questions. _Avoid_: user, human, operator.
- **Author**: in generation two, the agent that takes a request and writes the change itself. _Avoid_: implementer, implementing worker.
- **Requirements review**: in generation two, the review of a change against its requirements and the repo's written standards. _Avoid_: code review (names the tool), spec review, standards review.
- **Defect review**: in generation two, the review of a change for defects no requirement names and for size, by a reviewer that sees no other review of the change. _Avoid_: ponytail review (names the tool), final review (generation one's term).
- **Proven finding**: a review finding that is shown failing, or that names the line and the rule or requirement it breaks. A requirement the reviewer cannot confirm counts as one. _Avoid_: must-fix.
- **Unsettled finding**: a review finding about the change itself that no check could prove or disprove. _Avoid_: unproven finding (a finding the author has not yet tried to settle), concern, nit.
- **Follow-up ticket**: a ticket filed for a proven finding about code the change did not touch, or one that asks for more than the change's requirements. _Avoid_: tech-debt ticket.
- **Call-back**: a reviewer's second reading of a change, limited to the lines a fix changed. _Avoid_: re-check (a check is a command), re-review, follow-up review.
- **Miss**: a change that was not right first time. It is judged from the moment its PR is marked ready. _Avoid_: failure, rework.
- **Direct run**: one agent taking a request to its PR with no generation-one or generation-two skill and no reviewer. _Avoid_: baseline run, direct session, solo run.
- **Single-agent baseline**: the set of direct runs a comparison is made against. _Avoid_: baseline alone (generation one's term for a base commit).
- **Measurement record**: what is recorded about one finished unit of work: the facts its run knows and the cost and outcome found afterwards. _Avoid_: run record (the record of a multi-ticket run), metrics, telemetry.
- **Replay set**: the fixed set of finished tickets that every comparison between ways of working reruns. _Avoid_: benchmark, eval set.
- **Replay**: one run of a replay-set ticket from the commit before its merged PR. Its result is judged and never merged. _Avoid_: rerun, shadow run.
- **Cross-harness test**: the test that runs every generation-two path on every supported harness, started from one session. _Avoid_: compatibility test, harness matrix.
- **Proof run**: one run of one path on one supported harness in the cross-harness test. It is judged from the records it leaves, never from the harness's reply. _Avoid_: smoke test, trial run.
- **Guard probe**: the cross-harness test's run that tries each guarded command with a stand-in, to show it refused or held. _Avoid_: guard test, hook test.
- **Fixture repo**: the repo the cross-harness test's runs work on, returned to the same commit before each run. _Avoid_: test repo, sandbox repo.
- **Multi-ticket run**: in generation two, one run that takes two or more tickets from request to their PRs under a coordinator. _Avoid_: orchestrated run.
- **Feature run**: a multi-ticket run whose work-set comes from one spec. Its ticket PRs land on an integration branch, and it ends in a feature PR.
- **Backlog run**: a multi-ticket run over tickets that share no spec. Each ticket PR targets the default branch, and no feature PR follows.
- **Coordinator**: in generation two, the session that runs a multi-ticket run. It is a **delegator**, and the authors it starts are **executors**. It starts an author for each ticket, merges ready ticket PRs into the branch they target and keeps the run record. It changes no tracked file. _Avoid_: orchestrator, chief of staff, ticket owner.
- **Ticket PR**: in generation two, the pull request one author opens for one ticket. In a feature run it targets the integration branch; in a backlog run, the default branch.
- **Run record**: the durable record of one multi-ticket run: its work-set, the state of each ticket, and the decisions that cross tickets, each with its reason and who made it. _Avoid_: decision list (generation one's record, which holds decisions only), handoff file.
- **Claim**: in generation two, the assignment of a ticket made before an author starts on it. A claimed ticket is off the frontier. _Avoid_: start comment.
- **Main session**: the session a person started and talks to, at the head of any tree of agents it starts. _Avoid_: main thread, root session.
- **Delegator**: a session that hands whole tasks to **executors**, decides the trade-offs between them and checks their results. The **main session** is one whenever it hands tasks out. _Avoid_: orchestrator, manager, chief of staff.
- **Executor**: an agent a **delegator** starts to carry out one task and report its result. It chooses no model or **harness** for any part of that task and starts no other executor.
- **Helper**: an agent a **delegator** or an **executor** starts for a small piece of its own task, to keep that work's bulk out of its starter's context. Its result returns to its starter and is not checked on its own, and it starts no other agent.
- **Fan-out**: handing the independent parts of one non-ticket task to helpers, one part each. The session that fans out has no role name. _Avoid_: orchestrator mode, coordinator (the session that runs a multi-ticket run), delegation (handing a whole task to an **executor** or to a person).
- **Part**: one piece of a fan-out, which depends on no other piece.
- **Brief**: in generation two, the text an **executor** or a **helper** is given when it starts. A script writes it in a fixed form, and no agent adds to it. _Avoid_: handoff, prompt; local brief (a repo's own rules are run rules).
- **Author's report**: the fixed final message of an author a coordinator started: its PR, its final commit, its state, and each decision that affects another ticket. _Avoid_: handoff, summary.
- **Upstream dependency**: a skill this repo does not own or version that a generation-two path reads during a run, or whose output it works from. _Avoid_: fixed neighbour, companion skill.
- **Upstream contract**: the record of what generation two takes from each upstream dependency, and of what it supplies where that skill expects a person to answer. _Avoid_: pin, lock file.
- **Stack settings**: the one file in a repo, controlled by its owner, that sets how generation two behaves there. A repo without it gets every default. _Avoid_: config, local brief, the file the owner controls.
- **Run rules**: the rules a repo adds to generation two in prose, kept under one heading of its agent instructions. They may add to a skill but never contradict it. _Avoid_: owner notes, wiki, local brief.
- **Extension point**: the stack settings and the run rules together, the only place a repo changes generation two. _Avoid_: override, brief.
- **Preflight**: in generation two, the checks a run makes on its environment before the edit. Each ends in a stop or a warning. _Avoid_: setup check, environment check; check alone (a check is run against a change).
- **Guard**: a limit the environment applies to a command inside a generation-two run, whatever the agent's instructions say. The command is refused, or it waits for the owner's answer. Outside a run no command is refused. _Avoid_: hook (one harness's mechanism), guardrail (the snowman wrapper's), permission rule.
- **Run mark**: in generation two, the record that a run is in progress in one checkout or worktree. A guard applies only where one is present. _Avoid_: lock, session file.
- **Reach command**: a command a repo names that proves an environment its runs depend on can be reached. _Avoid_: health check, connection test.
- **Run grant**: in generation two, the writes other people can see that starting a run permits without asking. _Avoid_: permissions already granted (generation one's handoff phrase).
- **Lesson**: something that went wrong in a run, recorded with its sightings before any change is made for it. _Avoid_: retro finding, learning.
- **Sighting**: one run in which a lesson was seen. Its ticket is one of the lesson's cases, which a change made for the lesson is tested on. _Avoid_: occurrence, incident.
- **Lesson line**: the line in a run's final report that names a lesson, saying what went wrong and where it was seen. The owner turns it into a run rule, files it as a lesson, or drops it. _Avoid_: proposed rule, retro note.
- **Starting figure**: a number in generation two's design that was chosen, not measured. _Avoid_: default (the value a stack setting has when a repo sets none), threshold.
- **Text rule**: an instruction added to text a generation-two run loads. A repo's own are run rules. _Avoid_: patch, rule alone.
- **Repair**: a change that fixes wrong instructions or a stopped run and adds no behaviour. _Avoid_: fix (a fix answers a review finding), patch.
- **Rule ledger**: the record of each text rule added after launch, with its lesson and its cases. _Avoid_: changelog, rule list.
- **Path map**: the record of which text each generation-two path loads, and that path's word limit. _Avoid_: manifest.
- **Build stage**: one step in building generation two. Its tickets are cut from one spec, and only once the stage before it has ended. _Avoid_: phase, milestone; stage alone (a promotion's).
- **Retirement**: the one change that removes generation one's four skills and land from this repo. _Avoid_: deprecation, sunset, cutover.
- **Retirement gate**: the conditions that must all hold before retirement. _Avoid_: exit criteria, go-live check.
- **Actor** — the GitHub user whose activity a report describes; discovered at invocation time (the authenticated `gh` user), never committed to a repo, overridable per invocation. The actor bounds a report's scope: the report covers the actor's activity wherever it happened, across every account and repo.
- **Owner filter** — an optional per-invocation filter narrowing a report to one GitHub account's repos. When absent (the default), the report is actor-bounded and no owner filter applies. _Avoid_: owner (in generation two, the person who started a run).
- **Refusal**: the snowman wrapper's `Blocked` exception, raised by the guardrail or by target resolution and rendered once in `main` as `BLOCKED: <reason>` with exit code 2.
- **Target**: the resolved connection, environment, project root, snowman dir, and `.env` file for one snowman run, produced by `resolve_target`.
- **Branch diff**: the lines the checked-out branch adds and removes, measured from the point where it split from the default branch to the working tree. It is what the branch's PR would show if everything were committed now. _Avoid_: session lines, PR diff.
- **Session edits**: the lines Claude added and removed during one Claude Code session, whatever branch they landed on. Distinct from the branch diff.
- **Dossier**: a single HTML file that explains one system, process, finding or decision through numbered figures and tables, in the house style every dossier shares. _Avoid_: visual report, explainer, writeup (as names for the document).
- **Answer box**: the box at the top of a dossier stating the one claim the dossier defends. Every dossier has one, explainers included. _Avoid_: summary, TL;DR, verdict box.
- **Key findings**: the numbered list of three to five one-sentence findings directly under the answer box, each linking to the section that holds its evidence. _Avoid_: insights summary, highlights, executive summary.
- **Figure**: a numbered visual in a dossier, with a "So what" pull quote above its caption. Tables follow the same rule on their own counter ("Table 2"). _Avoid_: chart (for the general case), diagram (for the general case).
- **Caption**: the text beside a figure: one sentence on what it shows, then one to three points on how to read it. It never states the conclusion. _Avoid_: description, legend.
- **"So what" pull quote**: the conclusion the reader should draw from one figure alone, labelled "So what" and set large above the figure's caption, with its one key figure in coral. _Avoid_: so-what box, takeaway (takeaways are the section-level list).
- **Limits section**: the closing section of every dossier, listing what it could not establish. It stays when it says "None". _Avoid_: caveats, disclaimers.
- **Locked block**: the part of the dossier stylesheet (colour tokens, type scale, component styles) that every dossier carries unchanged. A dossier may change only the per-report geometry beside it. _Avoid_: theme, base CSS.
- **Visual family**: one of the named kinds of figure a dossier draws from, such as a DAG, a timeline or a comparison matrix. _Avoid_: pattern, chart type.
