# orchestrator-mode: fit against Anthropic's orchestrator and subagent guidance

Research date: 2026-09-03. Skill under review: `skills/orchestrator-mode/` (`SKILL.md` 143 lines, `README.md`, `plugin.json`,
`references/reference.md` 105 lines) at commit `47f7beb`. Primary sources read: the Claude Code docs at `code.claude.com` (sub-agents,
skills, tools-reference, worktrees, agent-teams, agents, env-vars; the old `docs.claude.com/en/docs/claude-code/...` URLs 301 to these),
the Claude platform Agent Skills overview and authoring best-practices pages (`platform.claude.com`; the old `docs.claude.com/en/docs/agents-and-tools/...`
URLs 302 there), the Agent Skills spec at `agentskills.io/specification`, the `anthropics/skills` README and `skill-creator/SKILL.md`,
the `anthropics/claude-code` `CHANGELOG.md` (raw, 6,219 lines, versions to 2.1.259), and four Anthropic engineering posts. The repo's own
standard, `~/.claude/skills/writing-for-agents/` (`SKILL.md` and `SKILL-MECHANICS.md`), and `scripts/lint_skill.py` were read as the
local conventions. Harness facts marked "observed" come from the tool roster this research session was itself given, not from a doc page.

## Verdict

**Mostly.** The skill is a strong orchestrator policy: it delegates everything, batches rather than atomizes, fans out in one message,
demands self-contained handoff prompts with return contracts, separates verification from implementation, isolates parallel writers in
worktrees, and bounds nesting. Frontmatter, description, and progressive disclosure all pass the spec and the repo's lint. The gaps are
concentrated in the Claude Code mechanics column of the reference, which has drifted from the current docs, plus a few missing
orchestrator-pattern elements from the first-party engineering guidance.

Top gaps, in priority order:

1. **Worktree base branch is wrong (hard contradiction).** The reference says worktrees "branch from HEAD, so uncommitted changes are invisible". Claude Code subagent worktrees branch from the repository's default branch on the remote (`origin/<default>`) by default, not the parent session's `HEAD`; only `worktree.baseRef: "head"` changes that. Under the documented default, committed-but-unpushed feature-branch work is invisible to the writers too, so the skill's "dirty tree" precondition is insufficient and the integration step can merge against the wrong base.
2. **Stale harness limits (hard contradiction).** The "200 subagents per session" budget and `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION` were removed in v2.1.224 and the variable is now a documented no-op. The concurrent (20) and depth (3) limits still hold.
3. **The plan/todo tool the skill leans on is absent by default on current models (hard contradiction).** `TaskCreate`/`TaskUpdate`/`TodoWrite` are not provided on Opus 4.8, Sonnet 5, Fable 5 and newer unless `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` is set. Workflow step 1 ("Write a TODO list") and Rule 1 need a fallback.
4. **Missing pattern elements from Anthropic's multi-agent guidance:** an explicit effort-scaling rule (how many dispatches and how much per dispatch for simple vs complex requests), a failure and resume policy (partial output at `maxTurns`, resume via `SendMessage` instead of re-dispatch), and a stated cost trade-off / when-not-to-delegate note that mirrors the docs' "use the main conversation when" list.
5. **Model-tier rule is internally contradictory (nit with behavioural effect).** Rule 5 says both "drop to a cheaper tier for simple or mechanical dispatches" and "never pass a tier below the session model".

## 6. Writing conventions

- No em or en dashes in `SKILL.md`, `README.md`, or `reference.md` (checked with a Unicode grep). One em dash remains in `plugin.json`. (c)
- Imperative voice throughout; consistent vocabulary (dispatch, worker, coordinator, return contract). Passes the best-practices "consistent terminology" check.
- `README.md` restates the eight rules in prose. It is human-facing and never loaded by the agent, so it costs no context load; it does cost maintenance as a second copy of every rule (`writing-for-agents` Pruning: single source of truth). (c) Trim the README's "What it does" to a pointer list once the rules settle.
- `reference.md` "Claude Code harness facts (verified 2026-07)" is the only dated statement and is where the drift in section 4 accumulated. (b) Prefer env-var names and doc links over numbers and dates.

## Recommended edits, prioritised

1. **Parallel Writes step 1 and Tool Mapping worktree row (a):** state that Claude Code subagent worktrees branch from `origin/<default>` by default; require `worktree.baseRef: "head"` (or a returned `base_sha` check against the intended tip) before dispatching parallel writers; keep the dirty-tree check as well. Cross-check `implement-feature`'s "every ticket dispatch gets worktree isolation" against the same fact.
2. **Nesting block (a):** delete the 200-per-session budget and its env var; change "excess dispatches queue" to "spawns past 20 running fail; batch the fan-out"; drop the "verified 2026-07" date and cite `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (3) and `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (20) by name.
3. **Plan tool row and Workflow step 1 (a):** note that task tools are off by default on current models (`CLAUDE_CODE_ENABLE_TODO_TOOLS=1` restores them) and give the "track the plan in the reply" fallback for every harness.
4. **New short paragraph, "Failure and resume" (b):** partial or failed return from a resumable worker is continued with `SendMessage` and the specific gap; Explore and Plan are one-shot and get re-dispatched; cap at three strikes, then report.
5. **Background execution note (b):** dispatches run in the background and return as notifications; workers cannot ask the user; `Agent` survives backgrounding so sub-orchestrators work. Replace "wait on" and `Monitor` in the delegation row.
6. **Effort scaling rule in Workflow step 1 (b):** one dispatch for a lookup, 2-4 parallel for a comparison or two-area change, waves for feature-scale work; start wide, then narrow.
7. **Rule 5 wording (c):** remove the contradiction between "drop to a cheaper tier" and "never pass a tier below the session model"; mention that allowlists and `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` can override the choice.
8. **Activation (b):** one sentence on the cost of the mode (fresh-context start per dispatch, summary-only returns) so the coordinator can flag a request that is too small for it.
9. **reference.md (b):** add a `## Contents` list at the top.
10. **Housekeeping (c):** remove the em dash from `plugin.json`; add `agent-tool` to keywords; consider `disallowed-tools` in SKILL.md frontmatter once the output-file carve-out is resolved; add "done when" clauses to Workflow steps; verify the Cursor and Cortex Code columns against those vendors' docs.
