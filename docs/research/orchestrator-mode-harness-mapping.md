# orchestrator-mode: Cursor, Cortex Code, and Codex columns checked against vendor docs

Research date: 2026-09-03. Companion to `orchestrator-mode-best-practices.md` (same date), which verified the Claude Code column of
`skills/orchestrator-mode/references/reference.md` (Tool Mapping table, lines 7-23, and the Nesting block) and flagged the Cursor and
Cortex Code columns as unverified. This note checks those two columns and adds OpenAI Codex, which the skill does not mention at all.
Skill at commit `47f7beb`. Primary sources only: `cursor.com/docs` and `cursor.com/changelog`, `docs.snowflake.com/en/user-guide/cortex-code/`,
`developers.openai.com/codex/...` (every page now 308s to `learn.chatgpt.com/docs/...`; both URLs are given), and the `openai/codex`
repository source read through the GitHub API. Where a doc page did not state a fact and the fact came from source code, the file path
is cited. Nothing was taken from forum threads or blog posts. Legend for status: (a) hard contradiction of the docs, (b) missing
element the docs offer, (c) nit.

## Verdicts

- **Cursor: partly correct.** The delegation tool (`Task`) and the read-only built-in (Explore) are right. Wrong or stale: the
  worktree row (Cursor has native per-subagent worktree isolation; a manual `git worktree add` is the fallback, not the method), the
  built-in roster (`Explore`, `Bash`, `Browser`, capitalised; there is no general-purpose built-in), the "todo tool" (only Plan Mode has
  plan/to-do tools; none is documented for Agent mode), the model row (model is set per subagent definition, not per dispatch), and the
  continue/stop row (background subagents can be resumed by ID). Nesting is two layers, not unlimited and not zero.
- **Cortex Code: partly correct.** `RunSubagent`, `EnterPlanMode`/`ExitPlanMode`, the `agent/<agentId>` branch, and the built-in
  trio are right. Wrong: "ask in the reply and wait" (there is an `AskUserQuestion` tool), "no per-dispatch override" (the task tool
  accepts `model:`), and "re-prompt" for continue/stop (background agents return an ID that can be queried and resumed). Missing: the
  `Review` tool (a built-in verification subagent, directly relevant to Rule 6), the `feedback` built-in, the 50-concurrent-background
  cap, and the rule that background agents cannot spawn background agents.
- **Codex: absent.** The skill has no Codex column. Codex has a documented orchestrator-worker mechanism (`spawn_agent`,
  `send_message`, `wait_agent`, `close_agent`, `followup_task`; built-ins `default`, `worker`, `explorer`; custom agents as TOML), a
  checklist tool (`update_plan`), Plan mode, and Agent Skills support from `.agents/skills/`. It has no native worktree isolation for
  subagents. A proposed column is at the end.

## 4. Cross-harness observations the skill should state

1. **Base branch is undocumented on Cursor and Cortex Code, and wrong in the skill for Claude Code.** Every worktree row should carry
   the same guard the companion note proposed: the writer returns `base_sha` and the integration dispatch checks it against the intended
   tip.
2. **Stateless is not the universal default.** Claude Code, Cursor, and Cortex Code subagents start clean; Codex subagents fork the
   parent's history unless `fork_turns: "none"`. The "Subagents are stateless by default" sentence in SKILL.md needs a Codex exception.
3. **Results arrive differently.** Claude Code: background by default, completion notification. Cursor: foreground blocks, background
   resumable by ID. Cortex Code: background returns an ID; get output or wait by ID; Desktop feeds the result back automatically. Codex:
   parent keeps working and calls `wait_agent`. Workflow step 3 ("collect each result") should say "via the harness's wait or resume
   mechanism, never by polling files".
4. **Nesting depth is harness-specific:** Claude Code 3 layers; Cursor 2 layers (the second cannot spawn); Cortex Code background agents
   cannot spawn background agents (foreground unstated), 50 concurrent background; Codex V1 one layer (`agents.max_depth` 1), V2 not
   depth-capped, 4 concurrent threads by default. The Nesting block should list these instead of "confirm before designating".
5. **Skills install paths.** `.agents/skills/` is read by both Cursor and Codex; `.claude/skills/` by Claude Code and Cortex Code CLI. A
   repo that targets all four ships the skill at both paths (or symlinks).
6. **Verification specialists exist on two harnesses:** Cortex Code `Review` tool and Cursor `Bash` built-in. The Subagent Selection
   section's "Build / verify code, run tests" row can name them.
