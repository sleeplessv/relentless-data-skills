2The 150-line budgetFigure 1

scripts/lint_skill.py sets LINE_BUDGET to 150 on line 35 and fails any SKILL.md above it with "SKILL.md is N lines (budget 150)" (line 160). CI's skill-lint job runs the linter on every push and pull request, and scripts/check.sh runs it locally. Figure 1 puts every SKILL.md against that line.

The source comment on lines 32 to 34 calls the budget "deliberately stricter than the docs' 500-line guidance". The point is progressive disclosure. The SKILL.md is loaded on every turn, so it carries the rules. Detail moves into references/, which the linter does not count and the agent reads only when a rule sends it there.

The linter checks more than length. It requires the name and description frontmatter keys, rejects unknown keys, caps the description at 1,024 characters, and demands a "Use when" clause unless DMI is true. It also enforces the side-effect rule from the first takeaway above: a file that runs git push or gh pr merge makes the skill DMI, or the skill must be allow-listed with a reason.

5How the render check runsFigure 4

A visual report is verified by skills/visual-report/scripts/check_render.py, 985 lines added on 2026-10-03 in commit 088a29f. SKILL.md (line 39) invokes it as uv run --no-project --with playwright python <skill-dir>/scripts/check_render.py <report.html>, with --shots DIR (default <report-stem>-check/ beside the report) and --timeout N (default 20 s). Figure 4 follows one run from the agent's command to the verdict line.

The timings are the constants at the top of the file. LOAD_TIMEOUT_S is 30, QUIET_MS is 2000, CALL_TIMEOUT_S is 10, PROBE_TIMEOUT_S is 15, and the default --timeout is 20. The overall limit is 30 + 20 + 90 = 140 s, and a daemon watchdog fires at 160 s. If the watchdog fires, the script marks the run incomplete and emits what it has with os._exit.

The script reads the rendered DOM, not the console. It snapshots diagram facts once, then opens tabs, toggles and <details> as a reader would and snapshots again. Each diagram is classified as error, rendering, lazy, unrendered, hidden, illegible, empty, clipped or ok (lines 242 to 271), with warnings for labels under 9 px or a diagram that runs past the window's right edge. Up to 20 suspect diagrams are re-rendered offscreen with the page's own Mermaid module, which is how the script learns whether the module ever loaded.

The script never trusts the console. It reads the rendered DOM twice, before and after opening hidden containers, re-renders suspect diagrams offscreen, and asks a known-good CDN URL whether the network is to blame before it lets an unrendered diagram count as a defect.

6How the verdict is decidedFigures 5 and 6

The verdict is 22 lines, verdict() on lines 354 to 375. Figure 5 shows them. Figure 6 maps each condition from the module docstring (lines 2 to 25) to the verdict it produces on its own. The exit codes are PASS 0, FAIL 1, BLOCKED 2, from EXIT = {PASS: 0, FAIL: 1, BLOCKED: 2} near the top of the file.

The function is a precedence ladder, and the order is the design. A defect the page proves on its own comes first. An environment problem comes second, because an unreachable CDN explains an unrendered diagram, so the script refuses to call that a page defect. The softer evidence, unrendered blocks and console errors, counts only once the network has been ruled out. That is why SKILL.md glosses BLOCKED as "unverified, not passing".

def verdict(result):    """Proof of a defect beats an environment problem, which beats softer evidence.     An error diagram, a 404, or a broken image is a defect whatever else went    wrong. An unreachable CDN explains unrendered diagrams and script errors,    so those count only when the network was fine.    """    if result.get("blocked"):        return BLOCKED    diagrams = result.get("diagrams", [])    requests = result.get("requests", [])    if (any(d["status"] in DRAWN_BAD and not d.get("env") for d in diagrams)            or any(r["kind"] == "defect" for r in requests)            or result.get("broken_images") or result.get("hung")):        return FAIL    if (any(r["kind"] == "blocked" for r in requests)            or any(d.get("env") for d in diagrams) or result.get("incomplete")):        return BLOCKED    if (any(d["status"] in NOT_DRAWN for d in diagrams)            or result.get("page_errors") or result.get("console_errors")):        return FAIL    return PASS
  1. 1361 result["blocked"] is set only when the check could not run at all (no Playwright, no browser, the script itself crashed), so it short-circuits everything else.
  2. 2365 DRAWN_BAD is {"error", "empty", "illegible", "clipped"}, statuses where Mermaid ran and drew something wrong. That is proof of a defect unless the probe marked the diagram env, meaning its module never loaded.
  3. 3367 A broken image or a frozen tab (hung) is a FAIL on its own, with no network excuse.
  4. 4369-370 A request classified "blocked" (a CDN host unreachable or answering 5xx), an env-flagged diagram, or a timed-out check means the page is unverified, so BLOCKED beats the softer FAILs below.
  5. 5372 NOT_DRAWN is {"unrendered", "rendering"}. With page and console errors, these count only once lines 369 to 370 have ruled out a network explanation.

9LimitsWhat this report cannot show

Four measurement choices bound what the figures above can claim.

  1. Commit counts include the 5 merge commits, and a commit that touches several skill folders is counted once per folder, so Table 1's commits column sums to 210, not 124.
  2. Skill-to-skill and test-to-skill edges in Figure 3 and Table 2 are grep- and import-based. A skill name that appears in prose counts as an edge, and nothing here verifies that the dependency is exercised at run time.
  3. "Tracked lines" in Table 1 and Figure 8 counts every git-tracked file in a folder with wc -l, including README and plugin.json, and treats binary assets (statusline's screenshots) as zero or a few lines.
  4. The sequence in Figure 4 was read from the source, not traced from a live run. No report was rendered to produce this content, and the CI job list reflects ci.yml at commit a590a62 only.
